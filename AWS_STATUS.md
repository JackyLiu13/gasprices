## The two bugs found and fixed along the way

**CloudFormation cannot resolve SecureString parameters.** The template
originally used `Type: AWS::SSM::Parameter::Value<String>`, which resolves at
deploy time and explicitly does not support SecureString — the only sensible
type for a secret. Fixed by passing parameter *names* and fetching values at
runtime with boto3. Better anyway: rotating a secret is now one
`put-parameter` call with no redeploy, and no secret ever enters the template,
the changeset, or `samconfig.toml`.

**`Policies` is not valid in SAM's `Globals` section.** Caught by
`sam validate --lint` before deploying. Moved onto each function.

## A verification mistake worth recording

Before deploying, the token was "verified" with `GET /repos/JackyLiu13/gasprices`,
which returned `permissions: {push: true}` — and that was reported as write
access confirmed. **It is not.** That field describes *your* permissions on the
repo, not the *token's* granted scopes. A read-only fine-grained PAT owned by an
admin still reports `push: true`.

There is no clean introspection endpoint for a fine-grained PAT. The only
reliable test is attempting the write you actually need:

```bash
TOK=$(aws ssm get-parameter --name /gasprices/github_token --with-decryption \
      --query Parameter.Value --output text)
curl -s -X POST -H "Authorization: Bearer $TOK" \
  https://api.github.com/repos/JackyLiu13/gasprices/git/trees -d '{"tree":[]}'
```

`403 Resource not accessible by personal access token` = read-only.

Relatedly, `github_store.py` was discarding GitHub's response body, so the
Lambda reported a bare `HTTP Error 403: Forbidden` with no reason. It now
surfaces the message, which distinguishes a missing scope from branch
protection from a bad path.

## After the token is fixed — verification order

```bash
# 1. Scheduled build
aws lambda invoke --function-name gasprices-build /dev/stdout
#    expect {"ok": true, "commit": "...", "summary": "1.689/L EXPENSIVE"}
#    and a new commit in the repo

# 2. Ingest endpoint, valid
SECRET=$(aws ssm get-parameter --name /gasprices/ingest_secret --with-decryption \
         --query Parameter.Value --output text)
curl -X POST "$LOG_URL" -H "x-gp-secret: $SECRET" \
  -d '{"station":"beaver","price":1.709,"source":"phone"}'
#    expect 200 + confirmation, a row in station_prices.csv, a rebuild

# 3. Ingest endpoint, wrong secret   -> expect 401
# 4. Ingest endpoint, no station     -> expect 400

# 5. Read the run rather than guess
sam logs -n gasprices-build --stack-name gasprices
```

Step 4 matters more than it looks: `log_price.py` reads "no station" as "this is
the regional benchmark", so an absent field would overwrite the series the whole
model is anchored to.

## Then, and only then — cutover

Run both schedulers in parallel for a few days and compare output. Only when
they agree, remove the `schedule:` block from `.github/workflows/update.yml`.
Keep `workflow_dispatch` and `repository_dispatch` as a free fallback — if AWS
ever breaks, one click still publishes.

**No firmware change at any point.** GitHub Pages keeps serving the same URL, so
the device never notices the backend moved.

## Cost

Expected **$0/month** — the usage sits inside permanently-free allowances. The
three ways to break that, all avoided in `template.yaml`:

1. **A VPC** → NAT Gateway ≈ $32/mo. This function needs plain internet; it has
   no `VpcConfig` on purpose.
2. **Secrets Manager** → $0.40/secret/mo. Using SSM Standard parameters, free.
3. **Default log retention is "never expire"** → a slow leak. Pinned to 7 days.

Teardown, if you ever want it gone:

```bash
sam delete --stack-name gasprices     # everything CloudFormation made
# SSM parameters are deliberately outside the stack; delete separately.
```
